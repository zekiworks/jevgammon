## Fix 1: rollback deletes only what this script inserted (`v3-players/`)

- **`insert --manifest M`** appends one record per row **this run inserted**: `{id, name, settings_sha256, inserted_at, rows_sha256}`, plus the DB path. The manifest is written after the commit.
  - A pre-existing identical row is reported "present, not recorded" and never enters the manifest.
- **`rollback --manifest M`** acts only on the manifest's ids:
  - each must still carry the recorded name and settings, else it refuses and deletes nothing;
  - unreferenced ids are deleted in one transaction;
  - an id referenced by `matches` or `league_players` is **kept**, named on stderr (`KEPT …`), and stays in the manifest; the exit status is then 1.
- **Tests:** `test_v3_players.py`, 6 OK (`test_v3_players-output.txt`). Scratch DBs are in memory or under ~/.cache, with v3.db's schema read-only. They show:
  - a pre-existing identical row survives rollback;
  - unreferenced inserted rows are removed;
  - an inserted but referenced row is kept and the CLI exits 1 naming it;
  - a changed recorded row is refused;
  - insert is exact and idempotent (the second run records nothing);
  - a name conflict is refused;
  - on a copy of today's players, insert only adds.
- **Production use, after approval:** backup (VACUUM INTO + zstd -t), `check`, then `insert --manifest ~/code/jevgammon/workspace/improve/v3-players-manifest.json`.

## Fix 2: coupled merge (`merge/`)

`merge_coupled.sh [--dry-run|--no-fetch] [--rollback OLD_CHAT OLD_DEC]`, defaults `improve` ← `origin/improve-small-2` and `improve-decision` ← `origin/improve-decision-small`.

1. Refuses unless both checkouts are on their branch with no tracked change.
2. **Before either merge:** both fast-forwards must be possible (`git merge-base --is-ancestor HEAD target`), and the **target** decision.py pin must equal the sha256 of the **target** chat improve.py. Otherwise nothing is touched (exit 2).
3. Merges decision, then chat. If the chat merge fails, decision is reset to its old head at once (exit 3).
4. Verifies the working files: pin == sha256(chat improve.py). Otherwise both are reset (exit 4).
5. Prints the rollback command.

`--rollback` resets decision, then chat, and verifies the same way.

- **Tests:** `test_merge_coupled.sh`, all 6 PASS (`test_merge_coupled-output.txt`), on throwaway `git clone --shared` copies under ~/.cache:
  - dry run;
  - target pin ≠ target chat file → refused before any merge;
  - chat not a fast-forward → refused before any merge;
  - second merge fails (`MC_FAIL_SECOND=1`) → decision reset at once;
  - full merge → both advanced, fence 564312da…;
  - rollback.
